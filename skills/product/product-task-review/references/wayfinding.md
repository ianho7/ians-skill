# 导航与定位：需要检查入口与层级时读取

沿主入口选定的任务检查定位，结果并入同一份审查。页面层级表达信息组织，不代表真实业务审批或交付链。

## 从中间进入

挑代表性的深层、详情与任务页面，从消息、搜索结果或收藏直接进入；同时检查首页怎样帮助陌生用户理解。前两层清楚不能证明深层结构清楚。

用 trunk test 检查第一眼能否辨认产品身份、当前页面、主要分区、本层去向、所在层级及适用时的搜索。无需先前点击记忆或长时间研究。单页工具不需要某元素时说明不适用，不为凑齐导航增加菜单。

区分全局、本地、辅助去向与当前位置，不让它们争同一级注意力。标题标识本页内容，高亮不能替代标题；源码有状态不意味着视觉上认得出。

追踪入口文字对落地页的承诺，名称无需完全一致但差异应可理解。检查返回上级、重新开始和访问线索是否支持找回内容；面包屑表示内容层级，不伪装成浏览历史。

## 解释产品与开始位置

首次进入能否说明这是什么、有什么、能做什么、为何值得使用，以及从哪里开始？内部人觉得显然仍需外部理解证据；口号、愿景或漂亮图像不能自动承担解释。

保留足够的解释和示例。推广的收益常归局部，杂乱成本由全部任务承担；入口冲突时提出主次及其他承载位置，不用同等显著性满足所有部门。

搜索范围不清时明确范围，筛选只在解决眼前困难时提供。任务表单可减少分心导航，同时保留必要定位和帮助。窄屏可让次要去向更深，但跨设备入口保持目的地，不无依据删任务。

需要观察理解时，先请用户说出所见用途与准备从哪里开始，再解释原型。专家找得到不是用户找得到的证据。
