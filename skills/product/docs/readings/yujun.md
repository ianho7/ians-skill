## 四个 skill 为什么这样分

| 入口 | 唯一主要职责 | 为什么值得保留在入口里 |
|---|---|---|
| `yujun-user-model` | 建立需求情境与行为选择模型 | 阻止把一个岗位或一个自然人误当成稳定需求，也阻止把功能建议、动机解释和行为证据混为一谈 |
| `yujun-switching-value` | 判断特定情境下是否值得换用 | 强制比较真实旧做法和替换负担；新方案自身好，并不等于有相对增量 |
| `yujun-exchange-map` | 还原各方交换、交接、成本与责任 | 阻止把页面跳转当业务闭环，以及只减少眼前步骤却把工作转嫁给别人 |
| `yujun-product-tradeoff` | 在明确目标和约束下比较行动 | 阻止为未经审查的目标优化、把局部改善当整体获益，以及把所有需求都变成开发项 |

这里保留的是会改变分析路径的约束，而非声称模型从未学过这些概念。通用访谈教程、完整经济学与心理学知识、偏误百科、通用 UX 检查表、招聘和职业路线没有搬进入口。问句可以自由生成，但必须落到具体业务情境、证据缺口和答案影响。

## 书中观点与本次改写的边界

| 内容 | 来源与处理 |
|---|---|
| 用户按需求情境而非单个人划分 | 书中核心观点；改写为可验证的行为模型，保留真实人、实际行为和后果，不把人简化为可以任意操纵的样本 |
| 新体验、旧体验与替换成本 | 书中框架；主体也说明难以数字量化。附录笔记出现主观打分示例，本套选择条件比较，不设统一总分 |
| “新用户旧体验为零”或“旧体验最小化” | 书中用于解释机会与参照系；本次明确：先核实线下、人工或不处理等旧做法，寻找低满足情境，不故意降低既有体验 |
| 效用四种满足程度 | 书中分类；本次要求按具体情境取证，不把“惊喜”自动排在底线之前，也不永久把某功能贴为某类 |
| 用户建议与真实反馈 | 附录有“不听建议”的强表达；本次改为不直接承诺也不一概否定，追查建议背后的经历，并分别判断需求与可行性 |
| 交换与利益分配 | 书中核心；本次扩成适合内部工具的链路问法，不强迫所有角色成为买卖双方；成本转移与消除必须分开 |
| 感知价值 | 保留主观认知影响选择的观点，同时分别列实际质量与感知；不把改变话术或用户认知当成真实能力改善 |
| 决策的信念、目标、行动 | 书中核心；本次改写为依据／因果假设、目标与行动的审查，不将“价值主观”推成“事实可以随意解释” |
| 访谈最多五题、对象／问句／答案影响、无资料先给问题稿 | 针对用户当前工作与表达偏好增加的交付约定，不是书中原有模板或定律 |
| 议程设置 | 书中介绍其推动作用与滥用风险；本次只保留明确待决问题、透明呈现反例，不提供隐藏代价促成拍板的脚本 |

书中损失厌恶的固定倍率、风险与收益的笼统等同、某些心理比例、医学与法律判断、历史平台措施、薪酬和行业预测，没有写成技能规则。它们不需要为本任务另开研究，也没有被本次独立证实。书中的劳动投入、性格测评和人才类别同样不作为普遍要求。

前两套强调产品发现与界面可用性，本套补交换、相对价值和权衡。三者有交集，入口按当前缺口选择；本套不假定所有组织都采用相同产品经理分工，也不把不同书中的角色边界硬合成一条规定。
