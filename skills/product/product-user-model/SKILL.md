# 按一次需求理解选择

把用户作为特定情境中的需求集合分析；同一个人在不同时间可以属于不同集合。复用已有业务链和案例，把事实、原话、解释分开。

## 建模

从一次事件还原触发、当时条件、原有做法、选择、结果和后续反应。只有原型时，能够确认的是页面表达，动机和真实行为仍是待核实解释。

围绕会改变选择的条件细分需求，例如赶时间、规则熟悉程度或失败代价。年龄、岗位和新老身份只有能解释行为差异时才保留；不为角色补写虚构履历。

区分用户掌握的信息、偏好、预期收益与实际结果。对重要解释提出竞争解释或反例；未使用可能来自触达、供给、规则或替代办法等原因，不能直接证明没有需求。功能建议先回到最近一次经历和代价，再判断其指向的问题。

用模型预测一个具体选择：什么条件下选 A，条件怎样变化会改选 B？注明已有样本覆盖什么、缺什么。案例条数不等于独立用户数，也不能推出总体占比。

## 交付与边界

给情境表：需求与触发｜当前选择及结果｜可能的选择依据｜材料依据／未知｜待验证预测。突出能改变设计判断的差异，以及能推翻当前解释的情形。

有关键缺口才附针对该解释的追问或观察，明确找谁、核实什么及答案影响；已有答案直接复用。模型足以区分关键情境、支持具体预测并显示证据边界后完成。

本项解释“为何这样选择”。是否优先解决归机会定义；新旧方案是否值得换归换用价值；不自动开展完整访谈或选开发优先级。

依据：《俞军产品方法论》“用户的定义”“如何理解用户的行为”及附录需求样本讨论。定位见[来源记录](../docs/sources.md)。
