# Ask Product

用户只需描述处境，不必记住九个技能。根据已有材料定位当前最影响下一步决定的缺口，推荐最短可用路径。

**在说明某技能的能力、推荐调用或建议跳过之前，先读取它的 SKILL.md。** 下表仅用于筛选候选，以实际文件的条件和边界为准；通常先读最相关的一两项。路径相对本文件，技能变化时以当前文件为准，缺失时如实说明。

## 从当前处境进入

| 当前最需要解决的事 | 候选入口 |
|---|---|
| 刚拿到原型，不清楚真实流程、上下游、规则或痛点，想带问题去问人 | [product-context-interview](../product-context-interview/SKILL.md) |
| 同岗位或同一个人在不同情境下选择不同，需要解释原因 | [product-user-model](../product-user-model/SKILL.md) |
| 有功能请求，却说不清真正的问题、影响与成功结果 | [product-opportunity-frame](../product-opportunity-frame/SKILL.md) |
| 新方案看似更好却没人用，或需要理解迁移与换用阻力 | [product-switching-value](../product-switching-value/SKILL.md) |
| 已有任务与原型，想找理解、操作、导航或状态上的障碍 | [product-task-review](../product-task-review/SKILL.md) |
| 问题明确，需要不同机制的新解法或更小的完整体验 | [product-solution-explore](../product-solution-explore/SKILL.md) |
| 已有选项，目标、多方利益或资源分配难取舍 | [product-tradeoff](../product-tradeoff/SKILL.md) |
| 有方案但缺证据，或只想准备一次可用性观察的主持稿 | [product-discovery-validate](../product-discovery-validate/SKILL.md) |
| 已有实际试用片段，需要挑严重问题并安排最小修复 | [product-usability-triage](../product-usability-triage/SKILL.md) |

按待决问题选路，而非只按“用户”“原型”“优先级”等词匹配。已有证据和阶段产物直接复用；材料不全不等于必须回到起点。已有明确任务的局部体验审查，可沿标明的假设开始；只有专家推演时不能宣称已有真实观察。

## 串联只发生在需要时

从零认识业务时，可从背景访谈开始；回答回来后，需要明确问题再做机会定义，需要新解法再做方案探索，需要证据再做验证。有实际观察且要安排修复时才进入分诊。每次只指出当前这一步及后续转向条件，不规定跑完全部入口。

用户模型用来解释情境差异，换用价值用来比较真实旧做法与新方案，按缺口插入；它们不是所有任务的必经阶段。只有目标冲突、多方利益或跨项目资源竞争时，再做正式取舍。

体验审查内部按需读取清晰度和导航参考，主持方法由验证入口读取。它们不作为额外技能要求用户记忆，也不生成重复报告。已有试用记录可以直接分诊，无需为了流程完整先重做验证。

## 给用户可执行的选择

先读用户已给的材料，复用已知背景。只有答案会改变推荐且无法从材料判断时，才问一个简短问题；其余未知写成可开始的假设或求证条件，避免背景调查表。

回复优先包含：当前首选技能及理由、它会交付什么、实际还缺的最少材料、一段结合现有任务可直接复制的提示词。必要时补一条“出现什么结果，再用哪项”的条件路径；通常一个首选已足够。

在提示词中沿用用户的具体文件、目标和已知事实，标明假设，说明本轮工作边界；不要把未发生的访谈或测试写成既有证据。环境未加载技能时给对应文件路径和读取指令，不假定命令已安装。

用户只问怎么选时，以推荐和提示词完成；用户已要求开始具体分析时，读取所选技能后在已授权范围内执行。导航本身不扩展为修改原型、联系他人或开发上线的授权。
